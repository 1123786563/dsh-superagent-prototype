# Superagent 看板替换建议

状态：源码调研与接入建议，尚未实施或修改运行中的插件。

用户参考：[Plane preview](https://github.com/makeplane/plane/tree/preview)。本建议将“替换当前 Superagent 菜单”理解为保留 DSH 左侧 Superagent 入口，替换其内部默认工作界面；是否改名、扩展为完整项目管理产品尚未确定。

## 1. 推荐第一版

以现有 Ticket 为卡片，提供默认看板、列表切换、搜索、来源筛选、排序和右侧详情。第一屏优先回答：有哪些任务在运行，哪些问题需要我介入。

- 页面占满 DSH 当前主区域；看板横向滚动，每列独立纵向滚动，列头固定。
- 顶部是当前仓库、搜索、看板/列表切换和执行器负载/暂停状态。
- 列头显示名称与真实总数，可折叠；空列保留空态。
- 卡片显示标题、已有 Issue/PR 关联、更新时间；待人工卡片优先显示问题、受阻或失败原因。
- 点击卡片在右侧打开详情，保留看板滚动位置和筛选；窄屏使用全宽详情。
- 详情提供现有的执行会话、来源线程、授权依据、重试、停止操作，并继续使用现有确认和错误处理。
- 来源、触发、评估、概览和设置保留在二级导航；不将它们混作同一看板的状态列。

以上是建议范围，尚未经过界面实现与浏览器验收。

## 2. 列与真实状态的对应

| 建议列 | 判定 | 说明 |
| --- | --- | --- |
| 待启动 | `stage === 'working' && action === 'queued'` | 已获授权，尚未启动 Assignment |
| 执行中 | `stage === 'working' && action !== 'queued'` | 由现有领域阶段定义，不等同于持续输出 token |
| 待人工 | `stage === 'person'` | 按 `answer/review/blocked/failed/delivery` 展示不同原因与操作 |
| 等待事件 | `stage === 'idle'` | 等待后续输入、线程事件或下一轮 |
| 已结束 | `stage === 'ended'` | 展示具体 outcome；包括合并、关闭、停止等，不能统一标为“已完成” |

依据：[阶段分类](../../src/core/stage.ts)、[领域约束](../001-domain.md)、[工单行投影](../../src/app/views/records.ts)。待人工可以排序靠前或通过快捷筛选单独查看；不复制同一 Ticket 到多个状态列。

## 3. 与 Plane 的交互边界

Plane 的跨列拖动会改变可编辑字段，并受权限、分组与 workflow 约束。Superagent 的阶段是执行事实的推导结果，现有管理 API 没有 `setStage`。

因此第一版采用自动归列，用真实的重试、停止、回复和 review 链接触发业务变化。若后续增加拖拽，必须先为每个允许的目标定义领域命令与前置条件，不能直接写 `stage`。

Plane 每列的“新增任务”也不能照搬。当前 Ticket 由 Eval 授权后创建；若需要“新建任务”，应设计“提交请求 → 评估/授权 → 建立 Ticket”，并定义来源、Mandate、回复渠道和审计记录。优先级、成员分配、自定义标签、多项目也是新增产品能力，不是换 UI 自动具备的字段。

## 4. 当前代码的接入位置

| 位置 | 当前职责 | 建议变化 |
| --- | --- | --- |
| [插件入口](../../src/client/index.tsx) | 注册 `main` 的 `dsh-superagent` 与 `sidebar.panellist` | 沿用当前入口及面板 key |
| [面板外壳](../../src/client/app.tsx) | 标题、全局搜索、六个 tab、页面选择 | 容纳看板布局与二级导航 |
| [路由](../../src/client/route.ts) | 默认 overview、页面和返回历史 | 增加默认看板、显示模式与详情定位；兼容旧路由 |
| [样式](../../src/client/client.css) | 外层滚动、内容最大宽 960px | 看板改全宽；把溢出限制在看板和列内部 |
| [工单详情](../../src/client/ticket.tsx) | 详情、授权、输入、线程、派工、操作 | 提取可复用内容，由抽屉和完整详情共同使用 |
| [面板上下文](../../src/client/provider.tsx) | API caller、本地化、通知、状态及重启处理 | 复用现有基础行为 |
| [工单视图](../../src/app/views/tickets.ts) | 按阶段过滤和分页 | 提供看板的列级分页及统计 |
| [工单投影](../../src/app/views/records.ts) | 标题、stage/action、note、attention、sessionId、summary、threads | 作为卡片数据来源 |
| [管理 API](../../src/app/api.ts) | 类型契约 | 若增加看板读取接口，同步定义响应 |
| [HTTP 路由](../../src/app/http.ts) | 当前 tickets 查询与 retry/stop | 新增看板读取接口时沿用现有访问检查 |

当前 `GET tickets` 默认只取 20 条，上限 1000，且 `open` 不含已结束。不能取一页后在客户端分组，再将每组数量标为全量。推荐新增只读 `GET board`（待实现），在同一次同步读取中计算五列的 total、首批卡片和分页信息。搜索与来源筛选应先应用到完整候选集，再分组、统计和分页，确保数字与结果一致。后续分页刷新应考虑工单跨列造成的重复或遗漏。

## 5. 实施与验收顺序

1. 先实现五列数据投影、准确统计与分页；复用现有领域分类，验证 queued、失败、等待 review 和各类结束结果。
2. 再替换面板外壳，接入真实卡片、列表切换、筛选、排序与空态。
3. 提取详情内容，加入右侧详情及关闭后的焦点、滚动位置恢复。
4. 检查重试/停止的权限、确认、失败反馈与刷新；保留设置保存行为和已有详情链接。
5. 完成类型检查、相关逻辑测试和构建，通过插件安装机制应用到当前 profile，在原 GUI URL 刷新验证桌面/窄屏、深浅主题。
